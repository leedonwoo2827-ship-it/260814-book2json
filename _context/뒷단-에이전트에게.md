## 0. 먼저 — 부탁이 하나 있습니다

**이 레포를 통째로 보냅니다.** 코드를 읽어 보시고, 그림을 갈아끼우는 자리를
**그쪽에 따로 만들어 주십시오.** 이유는 §5 에 적었습니다.

그리고 아래 원고 세 편을 **그쪽 파이프라인으로 직접 다시 만들어 보시고**,
이상이 있으면 알려 주십시오. 저희 쪽에서 재어 본 값은 다 적어 두었으니 대조하실
수 있습니다. 그 확인이 끝나야 다음으로 넘어갑니다.

원고는 레포 안에 같이 들어 있습니다 — `_context/보낼-원고/` 에 장별로 세 폴더.
**그냥 브라우저로 열어 보시면 압니다.** 그쪽은 이미 문제집 만드는 에이전트에게서
같은 꼴의 이론 요약 HTML(`1과목2.html` 계열)을 받고 계시니, 처음 보는 물건이
아닙니다. **같은 자리에 들어가는 같은 종류의 원고**이고, 나온 곳만 다릅니다 —
저쪽은 문제집에서, 저희는 책에서 뽑았습니다.

## 1. 무엇을 보내나

새뮤얼슨 『경제학』 5부에서 세 장을 뽑아 원고 세 편을 냈습니다.

```
19_원고.html    제19장 거시경제학 개요        27장 · 줄 123개 · 그림 23 + 표 4
20_원고.html    제20장 거시경제활동의 측정     28장 · 줄 136개 · 그림 23 + 표 5
21_원고.html    제21장 소비와 투자            24장 · 줄 118개 · 그림 16 + 표 8
```

19·20장은 `tools/split_sections.mjs` 에 그대로 넣어 확인했습니다. 경고가 없었고,
**저희가 센 줄 수와 그쪽이 센 줄 수가 정확히 같습니다.**

```
19장   표지 1 + 본문 27 + 마무리 1 = 29장 · 줄 123개
20장   표지 1 + 본문 28 + 마무리 1 = 30장 · 줄 136개
```

원고마다 같이 나오는 것:

```
이미지프롬프트.json          장마다 깔 가로형 그림 지시 (codex-prompt-img-studio 형식)
이미지프롬프트_부족분.json    다시 그려야 하는 장만 — 없으면 파일 자체가 없습니다
이름바꾸기.txt               번호가 밀린 그림 목록 — 없으면 파일 자체가 없습니다
실측.json                   장마다 잰 높이·줄 수. 그쪽은 안 읽어도 됩니다
```

## 2. 편지의 규약은 전부 지켰습니다 — 자로 재서 확인했습니다

말로 지킨 게 아니라 **playwright 로 960px 뷰포트에 띄워 장마다 실측**합니다
(`tools/measure.mjs`). 끊는 자리를 `split_sections.mjs` 와 똑같이 맞춰 놨습니다 —
제목을 찾고 그다음 형제부터 다음 제목 직전까지. 19장 실측 결과입니다.

```
19장   27장 · 줄 123개 (장당 최소 4 · 평균 4.6 · 최대 6)
       높이 최대 387px / 507px · 한 화면을 넘친 장 0개
       그림 23장 · 표 4장 · 그림도 표도 없는 장 0개

20장   28장 · 줄 136개 (장당 최소 4 · 평균 4.9 · 최대 6)
       높이 최대 417px / 507px · 한 화면을 넘친 장 0개
       그림 23장 · 표 5장 · 그림도 표도 없는 장 0개

21장   24장 · 줄 118개 (장당 최소 4 · 평균 4.9 · 최대 6)
       높이 최대 388px / 507px · 한 화면을 넘친 장 0개
       그림 16장 · 표 8장 · 그림도 표도 없는 장 0개

세 편 다 제목만 있고 몸통 없는 장 0개 · 가로 스크롤 없음
```

★ 20장은 처음에 한 장(`sam20-19`)이 그림 없이 나갔습니다. 이 검사기가 그 장을
  이름으로 집어 줘서 그 장만 다시 그렸습니다($0.12). **검사기가 없었으면 발표
  중에 알았을 일**이라, 이 단계를 만든 값을 했다고 생각합니다.

- `<body>` 바로 밑이 평평합니다. 감싸는 `<div>` 를 아예 **만들 수 없게** 조립기를
  짰습니다(`render/manuscript.py`) — 낼 수 있는 모양이 하나뿐입니다.
- `h1` 표지 · `h2` 묶음 · `h3` 장 하나. **`h3` 개수 = 슬라이드 개수**입니다.
- 한 장 6줄 이내. 모델이 넘기면 **코드가 자릅니다** — 말로만 시키면 안 지킵니다.
- `vh`/`vw` · `@import` · 외부 `<img src>` · `position:fixed` 없습니다.
- `<style>` 은 보내 주신 `1summary_planning.html` 의 것을 뼈대로 썼습니다.
  **치수는 한 글자도 안 건드렸습니다** — 944px 배치와 1.62712배 확대가 거기
  걸려 있는 것을 알고 있습니다. 바꾼 것은 색·굵기·여백뿐이고, 회사 PPT 템플릿의
  디자인 가이드를 따랐습니다(그린이 주조색인 가이드를 파랑으로 1:1 치환 —
  이 원고의 SVG 가 이미 파랑을 써서 두 갈래로 두면 한 화면에서 결이 갈립니다).
  첫 문단이 리드(굵은 파랑), 목록은 연한 파랑 사각 마커, 표는 머리행에 파란 띠,
  본문 글자는 슬레이트(#334155)입니다.
- `.q` 배지는 제목 안에만 있고 `<script>` 없이 label + checkbox 로 만들었습니다.

## 3. 요청하신 두 가지, 넣었습니다

### ① 안 바뀌는 이름표 — `data-id`

**전부 있습니다(27/27).** 선택이 아니라 이 앱의 뼈대로 넣었습니다.

```html
<h3 data-id="sam19-03"
    data-say="…"
    data-img="…">3 대공황이 낳은 학문, 고용법이 준 임무<label class="q">…</label></h3>
```

값은 `<책약칭><장번호>-<두 자리>` 입니다(`sam19-03`). 한 번 정하면 안 바뀌고,
장을 지우면 같이 사라지며 **재사용하지 않습니다.**

### ② 그 장에서 말할 문장 — `data-say`

**전부 있습니다(27/27).** 목차를 세울 때 장마다 같이 씁니다.
화면 문구를 옮긴 것이 아니라 **화면에 안 적힌 연결**을 적었습니다.

---

## 4. 새로 생긴 것 하나 — `data-img`

편지에 없던 것이라 미리 말씀드립니다.

```html
<h3 data-id="sam19-03" data-say="…" data-img="a wide horizontal flow of …, no text">
```

그 장 뒤에 깔 **가로형 그림의 영어 지시문**입니다. 지금 `s3b_images.py` 가
제목·본문에서 프롬프트를 조립하시는데, 원고에 이미 있으면 그것을 쓰시는 편이
낫습니다 — **화면 문구와 그림이 절대 어긋나지 않기 때문입니다**(같은 단계에서
같은 몸통을 보고 썼습니다).

속성을 파싱하기 번거로우시면 `</body>` 직전에 같은 것이 통째로 있습니다.

```html
<script type="application/json" id="imgprompts">{"by_id":{"sam19-03":{…}}}</script>
```

`#manifest` 를 꺼내 쓰시는 방식 그대로입니다. `<script>` 는 어차피 제거하시니
원고를 오염시키지 않고, `type` 이 JSON 이라 브라우저에서도 실행되지 않습니다.
값 안의 `<` 는 이스케이프해 뒀습니다.

### 저희 쪽에서 바라는 것 — `split_sections.mjs` 가 세 속성을 옮겨 주시면

지금 `split_sections.mjs` 는 `h3` 의 `data-id`·`data-say`·`data-img` 를
`<section>` 으로 안 옮깁니다(레포 전체에 참조가 없더군요). 셋을 `<section>` 과
`#manifest` 에 실어 주시면 세 가지가 한꺼번에 풀립니다.

- `data-id` — 손으로 맞춘 등장 시각이 **줄 번호(`73.4`) 대신 이름표에** 매달립니다.
  편지에서 짚으신 「앞에 항목이 끼어들면 뒤 번호가 전부 밀린다」 가 그대로 사라집니다.
- `data-say` — 글자 수 어림 대신 **실제로 말할 문장**으로 시간을 잡을 수 있습니다.
- `data-img` — `s3b_images.py` 가 조립하지 않고 그대로 씁니다.

## 5. 그림을 갈아끼우는 자리는 **그쪽에** 만들어 주십시오

이게 이번 편지의 본론입니다.

### 지금 그대로는 그림이 안 붙습니다

저희 원고에서 온 장은 `s2c-capture` 를 거쳐 전부 `media_kind: "html"` 로 잡힙니다.
그런데 `s3b_images.py` 가 그림을 받는 레인은 `WANT_MEDIA = {"text_image"}` 하나뿐이라,
**`html` 레인 장에는 그림 자리가 아예 안 생깁니다.**

번호는 이미 맞아 있습니다. 저희 JSON 의 `n` 은 **2번부터** 시작하고(1번은 표지),
`split_sections.mjs` 가 매기는 본문 장 번호와 정확히 같습니다. 19장으로 확인했습니다 —
`003.png` 는 3번 장에 그대로 붙습니다. **읽는 쪽만 열어 주시면 됩니다.**

### 그림은 글을 **갈아끼우는** 게 아니라 **뒤에 깔립니다**

프롬프트를 그렇게 쓰게 시켰습니다 — 「글자 없음 · 좌우로 펼침 · 1920×1080 프레임에
깔린다」. 글(제목·본문)은 HTML 이 그대로 얹히고 그림은 그 **배경**입니다.
HTML 을 그림으로 바꾸면 줄마다 하나씩 떠오르는 것도, 글자 선명도도 다 잃습니다.
편지에서 「캡처를 그만둡니다」라고 하신 그 이유 그대로입니다.

### 왜 저희 쪽이 아니라 그쪽인가

세 가지입니다.

1. **인증 주체가 다릅니다.** `s3b_images.py` 주석에 그쪽이 이미 적어 두셨습니다 —
   이미지 에이전트는 ChatGPT OAuth, 여기는 Claude 구독 OAuth고 **「브릿지를 만들지
   않는다. 접점은 폴더 하나」**. 저희도 그 판단을 그대로 따랐습니다.
2. **덱을 아는 쪽이 그쪽입니다.** 어느 장에 그림이 앉고 몇 초에 뜨는지는 덱의 일이고,
   저희는 덱을 안 만듭니다.
3. **저희는 원고만 씁니다.** 이 앱은 앞으로도 **책을 읽고 원고를 쓰는 작가**로만
   고도화할 생각입니다(사람이 그렇게 정했습니다). 그림을 만들거나 갈아끼우는 일은
   여기 들어오지 않습니다.

### 그래서 부탁드리는 모양

`이미지프롬프트.json` 을 받아 그림을 붙이는 자리를 **그쪽 레포 안에 따로** 만들어
주십시오. 저희가 내는 JSON 은 이미 `codex-prompt-img-studio` 가 그대로 먹는
아홉 칸 모양이고, `n` 이 그쪽 장 번호와 맞습니다. 접점은 지금처럼 **폴더 하나**면
충분합니다.

```
이 앱          →  <장>_원고.html  +  이미지프롬프트.json
그쪽(발표)     →  원고를 장으로 나눔. html 레인에도 그림 자리를 연다
이미지 스튜디오 →  003.png … 를 만들어 09_이미지/ 에 떨군다
그쪽(발표)     →  번호로 집어 그 장 배경에 깐다
```

### 이 앱이 **안 하는** 일 — 경계를 분명히

| | |
|---|---|
| 합니다 | 책 읽기 · 장 나누기 · 몸통 쓰기 · 인라인 SVG 그리기 · 실측 · 그림 지시문 쓰기 |
| 안 합니다 | **그림 만들기 · 그림 갈아끼우기** · 덱 조립 · 음성 · 자막 · 영상 |

원고를 고쳐 번호가 밀리면 `이름바꾸기.txt` 와 `이미지프롬프트_부족분.json` 을 내는
데까지가 저희 몫입니다(§10). **파일을 실제로 옮기거나 그림을 붙이는 것은 안 합니다** —
그림 폴더가 이 앱 밖에 있고, 남의 폴더를 건드리는 코드는 잘못 돌았을 때 되돌릴
방법이 없습니다.

## 7. 장마다 그림이 하나씩 있습니다 — 이게 이번 원고의 가장 큰 차이

**모든 장은 인라인 SVG 하나 또는 표 하나를 가집니다.** 줄글만 늘어놓는 화면을
만들지 않는 것이 이번 원고의 목표였습니다.

보내 주신 붙임과 견주면 이렇습니다.

```
            예전 원고(4과목 426장)   19장(27장)   20장(28장)   21장(24장)
그림               svg 5개           svg 23개     svg 23개     svg 16개
표                 tr 97개           표 4장       표 5장       표 8장
장당 줄 수  최소1 · 중앙값4 · 최대13   평균 4.6     평균 4.9     평균 4.9
```

426장에 `svg` 가 5개이던 것이 **장마다 하나**가 되었습니다. 그래서 부탁이 하나 있습니다.

> **`svg` 한 줄이 뜨는 시간을 글줄과 다르게 잡아 주시면 좋겠습니다.**

`auto_ats()` 가 글자 수에 비례해 시각을 나누는데, `<svg>` 는 글자 수가 0에
가까워서 **바로 다음 줄이 붙어 뜹니다.** 그림은 보는 데 시간이 걸립니다.
`min_step` 을 그림에만 크게(2.5초쯤) 주시거나, 그림 줄의 글자 수를 그 장 평균으로
쳐 주시면 될 것 같습니다. 저희 쪽에서 어림해 보면 그림 한 장에 3초 안팎입니다.

SVG 규격은 이렇게 맞췄습니다:

- `viewBox="0 0 520 190"` 언저리, **높이는 폭의 0.55배 이하**.
  세로로 길면 `max-height:240px` 에 걸려 통째로 작아지는 것을 알고 있어서
  비율에서 막았습니다(코드가 검사하고, 어기면 그 그림을 버립니다).
- `width`·`height` 속성 없음 — 폭에 맞춰 늘어나야 하니까요.
- `<image>`·웹폰트·`@import`·`<style>` 블록 없음. XML 파서로 실제로 검사합니다.
- 색은 파랑 네 단(`#1F4E79 · #2E75B6 · #9DC3E6 · #DEEBF7`) + 슬레이트
  (`#334155 · #94A3B8 · #CBD5E1`) 로 못박았습니다.
  ★ 보내는 세 편의 그림은 팔레트를 정하기 **전에** 그린 것이라, 관계선에 옛

## 8. 줄 세는 값이 양쪽에서 같습니다 — 맞춰 두었습니다

19장에 표가 4장 있고, 표 하나가 4~6행입니다. 편지대로 `<tr>` 하나를 한 줄로 세어
6줄 예산 안에 맞췄습니다.

처음에는 저희 실측이 **124줄**, `split_sections.mjs` 가 **123줄**로 한 줄 달랐습니다.
표 때문인 줄 알았는데 아니었고, 원인은 저희 쪽이었습니다 — 원고 끝에 넣은
`<script id="imgprompts">` 가 마지막 장의 다음 형제라 **그 장만 한 줄 더** 세고
있었습니다. 눈에 안 보이는 줄이라 사람이 알아챌 방법이 없었습니다. 고쳤고,
지금은 양쪽 다 **123줄**입니다.

혹시 그쪽에서 `<section>` 안의 요소를 세실 때도 같은 함정이 있을 수 있어 적어 둡니다
— 화면에 안 뜨는 형제(`script`·`style`·`template`)는 몸통에서 빼는 편이 안전합니다.

## 9. 안 지킨 것 · 다르게 한 것

정직하게 적습니다.

1. **`.q` 배지를 문번이 아니라 책 쪽수로 씁니다.** 단행본이라 모의고사 문번이
   없습니다. `<b>3</b>` 에 첫 쪽, 펴면 `책 3–4쪽` 이 나옵니다. 어차피 제목에서
   떼어 내시니 발표 화면에는 안 뜹니다. 사람이 책과 대조할 때 쓰는 칸입니다.
2. **`h1` 아래에 `<p>` 로 책 이름을 한 줄 넣었습니다.** 표지 부제로 쓰시면 됩니다.
   방해가 되면 말씀해 주세요, 빼겠습니다.
3. **`h2` 가 3~7개로 예전보다 적습니다.** 한 장(章)이 27장짜리라 묶음을 잘게
   나눌 이유가 없었습니다.

## 10. 원고가 고쳐지면 그림은 어떻게 되나 — 저희가 책임집니다

이쪽에서 원고를 고치면 슬라이드 번호가 밀립니다. 그러면 이미 만든 `005.png` 가
남의 장 그림이 되는데, **그 뒷정리는 저희가 합니다.** 프롬프트를 번호가 아니라
이름표에 매달아 두어서(`core/ledger.py`), 다시 내보낼 때 이렇게 갈라 냅니다.

```
몸통이 안 바뀐 장   프롬프트를 그대로 씁니다 (다시 안 만듭니다)
번호만 밀린 장      이름바꾸기.txt 에 005.png → 007.png 로 나옵니다. 다시 안 그립니다
새로 생기거나 바뀐 장  이미지프롬프트_부족분.json 에만 들어갑니다
```

그러니 **원고 파일이 바뀌면 통째로 다시 받으시면 됩니다.** 그림 쪽 정합성은
이쪽에서 맞춰 보냅니다.
