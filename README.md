> 산출물 폴더(`book2json-out-260814`)도 그 이름을 따르는데, 이미 만든 원고가
> 그 경로에 쌓여 있어 **일부러 안 바꿨다.** 바꾸려면 세 곳을 같이 바꿔야 한다:
> 폴더 이름 · `core/config.py`·`core/workspace.py` 의 환경변수 이름 · 산출물 폴더.

**단행본 한 장(章)** PDF 를 끌어다 놓으면 **발표 쇼케이스가 그대로 먹는 이론 요약
HTML 한 장**과 **AI 아바타가 읽을 대본**이 나온다. 끝에 나오는 것은 AI 아바타가
강의하는 슬라이드 영상이다.

받는 것이 「단행본 한 장」인 것이 이 앱의 이름(`작가 에이전트` · 칩 `단행본`)이
뜻하는 바다. 실기책·요약이론 같은 다른 재료는 **다른 앱**이 받는다 — 앞 칩이
그 자리다. 그래서 새 원고 화면이 아무 PDF 나 받는 것처럼 말하지 않는다.

```
단행본 PDF  →  [이 앱 · 5187]  →  <장>_원고.html   →  [발표 쇼케이스 · 5178]  →  mp4
                              →  <장>_대본.txt      (아바타가 읽을 글)
```

이 앱은 사슬의 가운데 토막이다. 혼자 쓰이지 않으므로, 나가는 파일마다 **받는 쪽**이
정해져 있다. `#/export` 화면이 파일마다 그것을 적어 준다.

★ **그림 지시(이미지 프롬프트)는 이 앱이 안 만든다.** 2026-08-14 결정 — 다른
  에이전트가 한다. 그래서 `b5-imgprompt`·`b8-export` 두 단계와 원장(`core/ledger.py`)
  ·부족분·이름바꾸기가 파이프라인에서 빠졌다. 코드는 지우지 않고 길만 끊었다
  (`pipeline/registry.py` 의 `_DEFS` 주석에 되살리는 법이 적혀 있다). 장 안에 들어가는
  **인라인 SVG(`b4-figure`)는 그대로다** — 그건 그림 지시가 아니라 원고의 일부다.

## 무엇을 지키는가

계약서는 `260812-summary-shocase/_new-context/5-이론화-에이전트에게.md` 다.
그 편지는 사람에게 "이렇게 써 주세요" 라고 부탁한 것인데, 이 앱은 부탁이 아니라
**구조로 못 박는다** — 조립기가 낼 수 있는 모양이 하나뿐이라 어길 방법이 없다.

- `<body>` 바로 밑이 평평하다. 감싸는 `<div>` 를 아예 안 만든다
- `h1` 표지 · `h2` 묶음 · **`h3` 하나 = 슬라이드 한 판**
- 한 판은 **944 × 507 px** 안에, **여섯 줄 이내**
- `<li>` 하나에 한 생각. 따로 나타나야 하는 생각은 따로 된 요소로
- `vh`/`vw` · `@import` · 외부 파일 참조 · `position:fixed` 없음
- 그림은 인라인 `<svg viewBox>` 로만

여기에 이 앱이 더하는 것 둘:

| | |
|---|---|
| `data-id` | **안 바뀌는 이름표.** 그림 파일이 여기 매달린다 |
| `data-say` | 그 장에서 말할 대본. **이 글자 수의 총합이 곧 영상 길이다** |

(`data-img` 가 하나 더 있었다 — 그림 지시를 제목에 심는 자리였다. 그 단계가 빠져
지금은 안 나온다. 되살리면 자동으로 다시 붙는다.)

## 길이 — 「몇 장」이 아니라 「몇 분짜리」로 고른다

2026-08-14 에 19장으로 만든 영상이 **5분 30초**였다. 15분을 기대한 자리였다.
원인은 `llm/prompts/outline.md` 가 `say`(장마다 말할 글)를 「한두 문장」으로 시킨
것이었다 — 장당 89자짜리 스물일곱 장은 어떻게 붙여도 6분을 못 넘긴다.

**영상 길이를 정하는 것은 화면에 적힌 줄이 아니라 `data-say` 총량이다.**

```
읽는 속도  330자/분 = 5.5자/초        ← 영상 만드는 쪽이 알려 준 값
목표 15~20분  =  대본 4,950 ~ 6,600자
장 수는 원문이 정한다 (1,700자당 한 장)   →  30장
장당 말 = 4,950 ÷ 30                      →  165자 (30초)
```

★ **330 은 읽는 쪽의 자다.** 여기 처음엔 420 이 적혀 있었다 — 19장 영상이 5분 30초
  였고 그 원고의 `say` 가 2,419자였으니 거꾸로 셈한 값이었다. 그 셈은 틀렸다.
  그때 저쪽은 `data-say` 를 읽지 않고 **자기가 지은 내레이션**을 읽고 있었으므로,
  우리 글자 수와 그 영상 길이 사이에는 아무 관계가 없었다. 재는 자와 읽는 자가
  다르면 **읽는 쪽의 자**를 써야 한다.

★ **목표는 점이 아니라 구간이다.** 모자란 것은 다시 만들어야 하고 넘치는 것은
  씬을 빼면 된다. 그래서 하한을 목표로 잡고 1.33배까지 허용한다.

★ **슬라이드를 무작정 늘리지 않는다.** 길이가 모자랄 때 장을 늘리는 것은 쉬운
  답이지만, 확인할 화면과 그려야 할 그림이 같이 늘고 원문 근거가 얇아진다.
  **먼저 장당 말을 늘리고**, 그것이 한 화면 35초를 넘길 때만 장을 더 만든다.
  그 증가도 **30분치에서 멈춘다** — 60분은 30분과 같은 장 수에 대본이 두 배다.

**원고 맨 위에 목표를 박아 보낸다.** 글자 수는 받는 쪽이 셀 수 있지만 목표는
못 센다 — 적혀 있지 않으면 음성을 다 구운 뒤에야 「짧다」를 안다.

```html
<meta name="lecture" content="20장 · 목표 15~20분 · data-say 6413자">
```

길이는 세 자리에서 보인다. **다 만든 뒤에 알면 늦기 때문이다.**

| 어디 | 언제 |
|---|---|
| 새 원고 화면의 표 | PDF 를 고르자마자 — 목표별 장 수·요약 비율·장당 말 |
| 목차 화면 | 장마다 「말 165자 · 30초」. 위 막대에 총합과 예상 길이 |
| 현황판 맨 위 | 「이 원고의 길이」 — 목표를 여기서 바꾸면 2번이 낡은 것으로 잡힌다 |

마무리(4번)는 `bak/<장>_대본.txt` 를 같이 낸다. `data-say` 는 속성이라 파일을
열어도 안 보이는데, 영상 길이를 정하는 것이 바로 그 글이라 눈으로 훑을 자리가
필요하다. 장마다 **자막(화면 표기)과 발음(TTS 에 넣을 글)**이 나란히 적힌다.

## 말투와 발음 — 눈으로 읽는 글과 소리로 듣는 글은 다르다

`say` 는 **AI 아바타가 읽는다.** 그래서 두 가지가 화면 글과 갈린다.

| | 화면에 적히는 줄 | `data-say`(소리) |
|---|---|---|
| 말투 | 해라체·명사형 — 「GDP 를 재는 두 길」 | **하십시오체** — 「…두 가지입니다」 |
| 표기 | 「1946년 · GDP · 25%」 그대로 | `data-read` 에 **「천구백사십육 년 · 지디피 · 이십오 퍼센트」** |

말투를 안 지키면 반말처럼 들리고(해라체는 높임이 없는 단계다), 체언으로 끊으면
그 문장에서만 말이 뚝 떨어진다. 목차 단계가 문장 끝을 세어 경고한다.

발음 쪽(`core/speech.py`)은 **모델을 안 부른다.** 숫자와 약어를 소리로 바꾸는 일은
규칙이 정확하고 공짜고 매번 같은 답이 나온다. 바꿀 것이 없는 장은 `data-read` 를
아예 안 단다 — 같은 글을 두 번 실으면 받는 쪽이 「무엇이 다른가」를 찾아야 한다.

## 왜 번호가 아니라 이름표인가 — 넘겨주는 쪽이 알아야 할 것

원고를 눈으로 보고 고친 **뒤에** 그림을 만든다. 그런데 그림 파일은 슬라이드 번호로
이름이 붙는다(`005.png` = 5번 장). 앞에 장이 하나 끼어들면 번호가 전부 한 칸씩
밀리고, `005.png` 는 남의 장 그림이 된다. 예순 장짜리 원고에서 두 번째 장을 하나
늘리면 쉰여덟 장의 그림이 통째로 어긋난다.

그래서 이 원고는 장마다 **안 바뀌는 이름표(`data-id`)**를 달고 나간다. 그림을
만드는 에이전트는 **번호가 아니라 이 이름표에 그림을 매달아야 한다.** 번호는
원고를 한 번 고칠 때마다 밀리지만 이름표는 안 밀린다.

이 앱이 그 원장을 들고 있던 코드는 `core/ledger.py` 에 그대로 있다 — 몸통이 안
바뀐 장은 다시 안 만들고, 밀린 번호는 `005.png → 007.png` 표로 뽑던 것이다.
그림을 맡는 쪽에서 같은 문제를 풀 때 읽어 볼 만하다.

## 설치

```
setup.bat            (macOS/Linux 는 ./setup.sh)
```

- Python 3.10+ 와 `claude` CLI(Claude Code) 가 있어야 한다.
  **API 키가 아니라 구독 OAuth** 를 쓴다 — 터미널에서 `claude` 를 한 번 실행해
  로그인해 두면 된다. 부모 환경에 `ANTHROPIC_API_KEY` 가 있어도 자식에서 비워

- `npm` 이 있으면 playwright 도 깐다. **b7(실측)에만 쓴다** — 없으면 그 단계만
  건너뛰고 원고는 그대로 나온다(다만 규약을 어겼는지 모르는 채로 나간다).

## 네 단계

사람이 누르는 것은 넷이고, 돈이 드는 것은 가운데 둘뿐이다.

| | 누르는 것 | 단계 | 무엇 | Claude |
|---|---|---|---|---|
| 1 | 책에서 글 뽑기 | `b1-pdf` | 쪽별 본문. 머리글·쪽번호·여백 상자를 걷어낸다 | ✗ |
| 2 | 장 나누기와 대본 | `b2-outline` | `h2` 묶음 + `h3` 장 + **대본.** 여기서 장 수와 영상 길이가 정해진다 | opus |
| 3 | 몸통 쓰기 | `b3-write` | 장별 몸통. 여덟 장씩 묶어 부른다 | opus |
|   | | `b4-figure` | 장마다 인라인 SVG. 여섯 장씩 | opus |
| 4 | 마무리 | `b6-assemble` | 원고 + 대본을 파일로 | ✗ |
|   | | `b7-check` | 진짜 브라우저에 띄워 장마다 높이를 잰다 | ✗ |

`b5-imgprompt`(이미지 프롬프트)와 `b8-export`(내보내기)가 빠진 자리라 번호가
`b6` 으로 건너뛴다. **번호를 다시 매기지 않았다** — 캐시 파일 이름이 단계 키라,
바꾸면 이미 만든 원고의 캐시가 통째로 미아가 된다.

**Claude 단계는 낡아도 자동으로 안 돈다.** 돈은 명시적 클릭에만 쓴다.
프롬프트 파일(`llm/prompts/*.md`)이 캐시 해시에 들어가 있어서, 프롬프트만 고쳐도
그 단계가 낡은 것으로 잡힌다.

## 그림을 맡는 에이전트에게 — 가로형에 대해 알고 갈 것

이 앱이 그림 지시를 만들 때 알아낸 것이라 남겨 둔다. **진짜 16:9 는 없다.**
`codex-prompt-img-studio` 의 `_ASPECT_SIZE` 는 `landscape`·`horizontal`·`16:9` 를
전부 같은 값 `1536x1024` 로 떨어뜨리고, gpt-image 의 네이티브 크기는
`1024x1024 / 1536x1024 / 1024x1536` 셋뿐이다. **가장 넓은 것이 3:2** 다.

받은 샘플(`_contex/…이미지프롬프트 (1).json`)이 `square` 인 이유는 그쪽 앱의 사진
자리가 세로 패널이어서 "landscape 로 두면 좌우 30~40% 가 잘린다" 는 판단이었다
(`260804-ppt2eduvideo/core/deck_builder.py:1679`). 이 원고는 반대로 1920×1080 프레임에
깔므로 그 제약이 없다.

★ `aspect` 만 바꾸면 안 된다. 샘플은 `"square 1:1 composition … center-cropped"`
가 **34개 프롬프트 본문에 전부 박혀** 있어서, `aspect` 만 `landscape` 로 돌리면
가로 캔버스 한가운데 정사각형 그림이 앉고 좌우가 빈다. 구도 문구까지 같이 써야
한다 — 이 앱이 쓰던 문구는 `pipeline/b5_imgprompt.py::style_hint` 에 있다.

## 발표 쇼케이스에 넣는 법

1. `#/export` 에서 `<장>_원고.html` 을 내려받거나 경로를 복사한다
2. 쇼케이스(`localhost:5178`) → **새 발표** → **참고 자료** 칸에 끌어다 놓는다
3. `kind === "html"` 로 잡혀 `s2c-capture` 가 돌고, **`h3` 수 + 1(표지)** 만큼 장이 생긴다

직접 확인하려면:

```
node <쇼케이스>/tools/split_sections.mjs <원고.html> --out /tmp/x2.html
```

## 남은 것 — 발표 쇼케이스 쪽에서 할 일

`split_sections.mjs` 는 지금 `h3` 의 `data-id`/`data-say` 를 `<section>` 으로 옮기지
않는다(그 레포 전체에 `data-say`·`data-id` 참조가 하나도 없다). 저쪽을 업데이트할 때:

- `split_sections.mjs` 가 두 속성을 `<section>` 과 `#manifest` 로 옮기게 한다
- `htmldoc.py` 가 `manifest` 에서 `say` 를 읽어 **내레이션으로 그대로 쓴다.**
  지어내지 않아도 된다 — 이 앱이 장마다 목표 길이에 맞춰 써서 보낸다
